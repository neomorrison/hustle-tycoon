# 3D world: asset contract, pipeline and runtime

The room scenes in **Dropship Tycoon** and **Hustle Tycoon** used to be flat 16:9 images with invisible hotspot
boxes. They are now live three.js dioramas built from GLB models that headless Blender generates from Python
scripts. Characters are rigged, animated and walk around. The feel we are after: **The Sims** (a cutaway room you
can rotate and zoom, a person with needs who walks to the bed, fridge and desk and visibly does things) crossed
with **Game Dev Tycoon** (a team at desks, typing, with point bubbles popping over their heads).

Both repos carry identical copies of `blender/`, `src/three/` and `public/assets/3d/`. `dropship-tycoon` is the
canonical source; hustle-tycoon copies it. Everything below is a contract: builders of assets and the runtime work in
parallel against it. Do not rename anything listed here. Additions are fine if you document them in this file.

---

## 1. Look

- Stylized, soft, toy-like low poly with **bevelled edges** (bevel modifier, 1–3 segments, applied on export), like
  The Sims 4 build mode or a Two Point / Game Dev Tycoon diorama. Rounded forms, no hard CAD edges, no realism.
- **No textures.** Flat PBR colours from the shared palette (section 4), roughness 0.55–0.9, metallic 0 except metals.
  Detail comes from geometry: cushions, trims, drawer handles, cables, books, plants, posters as coloured panels.
- Rooms are **dioramas**: the floor sits on a visible slab (0.25 m thick, `m_slab` colour) floating in space. Every room
  has 4 walls; the runtime cuts away walls that face the camera (section 6).
- Light-first: warm cream / pastel walls, light wood floors. Tier 5 (penthouse) is the exception: night skyline outside.
- Scale: 1 Blender unit = 1 metre. Standard door 0.9 × 2.1 m, desk top 0.75 m, chair seat 0.46 m, bed top 0.5 m,
  counter 0.9 m, wall height 2.7 m (loft/penthouse 3.4 m). People are ~1.7 m tall with slightly big heads (1:6 ratio).
- Readability over detail: every interactive object must be recognisable at 300 px wide from the default camera.

## 2. Coordinates

- Blender: Z up. Room floor top at z = 0, floor centred on the origin. Walls: **north = +Y, east = +X, south = −Y,
  west = −X**. The default camera looks from the **south-east, high** (from +X −Y toward the origin), so the
  **north and west walls are the visible back walls** in the default view. Put the main door, windows you care
  about, and every interactive object where it reads from that view (against the north/west walls or free-standing).
- glTF export converts to Y up: Blender (x, y, z) → three.js (x, z, −y). North (+Y Blender) = −Z in three.js.
- **Forward convention.** Characters face Blender **−Y** (= glTF/three.js **+Z**, the glTF "front"). Anchors (empties)
  use the same convention: an anchor's local **−Y** axis (Blender) is where a character placed on it faces. In three.js
  an actor placed with `actor.position.copy(anchor.worldPos); actor.quaternion.copy(anchor.worldQuat)` faces the right way.
- Names: lowercase `[a-z0-9_]` only (three.js sanitises other characters). Every node name is unique inside its file.

## 3. Pipeline (`blender/`)

```
blender/
  run.mjs              node runner: `node blender/run.mjs <target...|all> [--preview] [--stills]`
                       finds Blender (env BLENDER, else C:/Program Files/Blender Foundation/Blender 5.1/blender.exe,
                       else the newest "Blender x.y" folder, else `blender` on PATH), runs each script with
                       --background --factory-startup --python, fails loudly on Python errors
  lib/                 shared Python (importable via sys.path insert in each script)
    palette.py         the colour palette + material factory (section 4)
    build.py           primitives (rounded box, cylinder, bevel), grouping, custom props, anchors, lights,
                       glTF export with the right flags, preview renders
    furniture.py       reusable furniture/prop builders (bed, desk, chair, monitor, fridge, …) with style params
    room.py            room shell builder: floor, slab, 4 walls with openings (doors/windows), baseboards, trims
  rooms/<id>.py        one script per room id (tier0 … tier5, mcdoodles, title_city, studio)
  character/character.py   rig + body + hair/accessories + morphs + animation clips
  props/props.py       hand props, gear props, inventory boxes (one GLB)
  stills.py            renders room stills + regenerates public/assets/rooms/hotspots.json and seats.json (section 9)
  .previews/           preview PNGs (gitignored)
```

- Output: `public/assets/3d/<id>.glb`. Scripts are deterministic (no unseeded randomness; seed `random` explicitly).
- Export flags (glTF 2.0 binary): apply modifiers, **export custom properties as extras** (`export_extras=True`),
  no cameras, **no lights** (the runtime makes its own), +Y up, selected hierarchy only, animations for the character.
  After export, optionally run `npx gltf-transform meshopt` (compress only, never `optimize`/`join`/`flatten`, which
  rename or merge nodes). The runtime registers the meshopt decoder, so either form loads.
- Preview renders (Eevee, 1280×720) go to `blender/.previews/<id>_*.png`. Builders must look at them and iterate.
- Budgets: room ≤ 90k triangles and ≤ 2.0 MB GLB; character ≤ 12k triangles (all hair/accessories included) and ≤ 1.5 MB;
  props ≤ 0.8 MB; title_city ≤ 120k triangles.

  `m_mouth`, `m_acc` (accessory base colour), `m_acc2`. The runtime clones these per actor and recolours them.

## 5. Room GLB contract (`public/assets/3d/<roomId>.glb`)

Room ids: `tier0` … `tier5` (home/office ladder, shared by both games), `mcdoodles` (dropship work location),
`title_city` (title screen diorama, section 8), `studio` (the character preview pedestal, section 5a).

Hierarchy (every node name lowercase, unique):
```
room                       empty. extras: {room:"tier0", w: <floor width m, X>, d: <floor depth m, Y>, wallH: 2.7}
  floor                    mesh, extras {floor:true}. Rugs are separate meshes on top (not obstacles).
  slab                     the thick base under the floor
  wall_n, wall_e,          one node per wall (a mesh; openings modelled, not boolean-ed at runtime).
  wall_s, wall_w           extras {wall:"n"|"e"|"s"|"w"}. Wall-mounted decor (windows, posters, shelves, clocks,
                           curtains, wall TV) is PARENTED to its wall so it hides with it. Doors are NOT parented
                           to walls (they are interactive, see below).
  <furniture groups>       one empty per piece of furniture with its meshes as children, e.g. `bed`, `nightstand`,
                           `couch`, `bookshelf`, `plant_1`. extras {obstacle:true} when people can't walk through it.
                           Interactive ones add {interact:"<key>"} (keys below).
  staffdesk_1 … _N         desk + chair + monitor sets for Hustle staff, extras {staffdesk:n, obstacle:true}.
  a_*                      anchors (empties, plain axes, 0.3 m display size), see below
  l_*                      light anchors (empties) extras {light:"lamp"|"ceiling"|"window", color:"#ffd9a0",
                           intensity:<0..3 relative>, distance:<m>}. At least one per room.
  outside                  optional group for things beyond the walls (skyline, trees, street) extras {outside:true}.
                           A child group with extras {sector:<Blender degrees, 0 = east, 90 = north>} is a cutaway
                           sector: the runtime sinks it out of view while it is on the camera's side (tier5's city).
  (any group)              extras {gear:"<props id>[,<id>]"} = the room already shows that gear as furniture
                           (section 7, "Baked gear"); setGear never places a duplicate
```

**Interactive keys** (`interact` extra on the furniture group; picking and hover highlight use the whole group):
- Homes (`tier0`–`tier5`): `bed`, `computer` (the main desk with the player's computer), `fridge` (the kitchen corner:

- `mcdoodles`: `counter` (front counter with registers), `fryer` (fry station + grill line), `exit` (glass exit door).

**Staff desks per tier** (Hustle staff slots; the founder uses the main `computer` desk):
tier0: 0 · tier1: 1 · tier2: 2 · tier3: 3 · tier4: 5 · tier5: 7. Place them so all seated people are visible from the
default camera and not hidden behind each other. Dropship shows or hides them per its own staff.

**Walkability.** The runtime builds a 0.2 m grid over the floor, blocks cells under every `obstacle` group's footprint
(plus 0.15 m padding) and under walls, and runs A*. Keep at least a 0.8 m wide clear path from `a_door_stand` to every
anchor. Stand/sit anchors may sit inside an obstacle's padded footprint (chairs are part of desks): the runtime walks to
the nearest free cell, then glides the last metre.

**Room programme.** Each builder must also match the in-game fiction (see `SPEC.md`/`src/data/apartments.ts` in
dropship and `src/data/offices.ts` in hustle):
- `tier0` Parents' / Mom's basement (~6.5 × 5 m, wall_panel walls, carpet): twin bed with a messy duvet, old desk with a
  clunky laptop + desk lamp, mini fridge + microwave on a small counter (stove = hot plate), wooden stairs up to a door
  (the front door is at the top of a short stair run against the north wall or a door at floor level beside the stairs),
  saggy couch, washing machine, laundry basket, stacked moving boxes, a small high window (window well).
- `tier1` Shared apartment bedroom + kitchenette (~6 × 5 m): full mattress on a low platform, posters, string lights,
  cheap white desk + laptop, kitchenette (fridge, sink, 2-burner stove, microwave), hallway door, bean bag, plant, 1 staff desk
  (a folding table with a laptop is fine: "your office is the kitchen table").
- `tier2` Studio (~7.5 × 6 m): queen bed, desk nook with monitor + ring light, kitchenette with tall fridge and stove,
  small dining table, front door, big south-facing window, neon "HUSTLE"-style sign made of coloured tubes (no letters
  required; abstract squiggle), 2 staff desks.
- `tier3` Creator loft (~10 × 7.5 m, 3.4 m walls, brick north wall, factory windows): king bed on a platform, standing
  desk with dual monitors, filming corner (camera on tripod, softbox), open kitchen with island + stools + fridge,
  metal front door, plants, couch + rug, 3 staff desks.
- `tier4` House + garage HQ (~12 × 9 m single storey, open plan): bedroom zone, office zone with a 3-monitor desk,
  kitchen with fridge, living zone, garage zone (concrete floor, roll-up door on the east or south wall, metal shelving
  = `garage`, packing table), half-height interior partitions (≤1.2 m) so every zone is visible, 5 staff desks.
- `tier5` Penthouse HQ (~13 × 10 m, 3.4 m walls, floor-to-ceiling window walls on north + west, dark floor, backdrop
  dark navy; `outside` = a night city FAR BELOW: a city floor 34 m down in `m_window_sky` (tinted with the sky, so it
  is haze by day and melts into the navy at night) with glowing street lines, and blocks of towers whose roofs all stay
  at least 7 m under the room's floor, in eight cutaway sectors; nothing ever rises between the camera and the room): king bed on a platform, executive desk with 2 ultrawide monitors,
  designer kitchen with built-in fridge + island, lounge with sectional sofa, brushed-metal elevator door (= `door`),
  7 staff desks in a sleek open office cluster.
- `studio` (section 5a): the character preview pedestal, no walls.
- `mcdoodles` (~11 × 8 m): red/yellow burger restaurant. Front counter with 2 registers, fryers with fry baskets, grill
  with patties, drinks machine, menu boards (abstract burger/fries/drink pictograms, no letters), glass exit door, 3 booths
  (6 seats), checkered floor, trash bin. The kitchen is behind the counter (north side); the dining room is south.

**No hanging fixtures.** The cutaway has no ceiling, so pendants, globes and bulbs on cords read as floating objects.
Rooms place only the `l_*` light anchor where the bulb would hang (`F.ceiling_light`); hanging decor next to a wall is
parented to that wall's decor so it hides with the wall.

### 5a. Studio (`public/assets/3d/studio.glb`)

The character preview for the new-game "Look" step in both games. A round pedestal 2.4 m across (soft rounded rim,
blush top on a dusty rose drum, a thin white ring inset), no walls, no furniture. `a_spawn` at the centre facing the
default camera, one `l_key`, root extras `{room:"studio", studio:true, w:2.4, d:2.4, wallH:2}`. Checked with
`node blender/inspect.mjs public/assets/3d/studio.glb --check studio`. The runtime frames it differently from rooms
(section 6, "Studio"): one person, full body, at any aspect, drag turns the pedestal.

## 6. Runtime (`src/three/`)

Vanilla three.js (`three` ^0.186), TypeScript strict, no React inside `src/three/` except `src/three/react.ts`
(one small hook). Game code only talks to the public API below. The types already exist in `src/three/types.ts`
(the source of truth for the shapes sketched here); `src/three/index.ts` re-exports them.

```ts
// src/three/index.ts (the whole public surface; the types live in src/three/types.ts)
export function webglAvailable(): boolean               // false in Node/tests; cached
export type RoomId = 'tier0'|'tier1'|'tier2'|'tier3'|'tier4'|'tier5'|'mcdoodles'|'title_city'|'studio'
export interface StageOptions {
  canvas: HTMLCanvasElement
  url: (path: string) => string          // maps '3d/tier0.glb' → full URL (the game's asset() helper)
  quality?: 'low' | 'high'               // low: pixelRatio 1, 1024 shadows, no MSAA
  onHover?: (key: string | null) => void  // interactive key or 'actor:<id>' under the pointer (never 'floor')
  onPick?: (pick: Pick3D) => void         // key: interactive key | 'actor:<id>' | 'floor'; point = hit in room coords
  onReady?: () => void                    // first room + characters loaded and rendered (fires once)
  onError?: (err: unknown) => void        // load/GL failure (fires once): the game falls back to its 2D scene
  placeholderActors?: boolean             // dev/lab only: capsule people when character.glb is missing (no onError)
}
export class Stage {
  constructor(opts: StageOptions)
  setRoom(id: RoomId, opts?: { staffDesks?: number }): Promise<void>   // swap rooms with a short fade
  setStaffDesks(n: number): void          // show staffdesk_1..n, hide the rest (also re-blocks the walk grid)
  setTimeOfDay(hour: number): void        // 0..24 float; drives sun/hemi colours, windows, lamps
  setSpeed(mult: number): void            // animation/walk speed multiplier 0..8; 0 = frozen (game paused)
  setActive(on: boolean): void            // stop/start the render loop (e.g. while a fullscreen overlay covers it)
  setCameraMode(mode: 'room' | 'orbit'): void  // 'orbit' = slow auto-rotate with the per-yaw title framing
  rotate(stepDeg: number): void           // animated yaw step (studio: turns the pedestal)
  zoom(delta: number): void               // delta > 0 zooms IN (one unit = one 0.8x step), < 0 out; clamped
  resetView(): void                       // animate back to the default yaw / zoom / pan
  highlight(key: string | null): void     // programmatic hover glow (keyboard focus, tutorial)
  // actors (people)
  setActor(id: string, spec: ActorSpec): void   // create or update look/name; idempotent
  removeActor(id: string): void
  task(id: string, t: ActorTask): void          // declarative; same task again = no-op; new task = walk there, then act.
                                                // The FIRST task of a new actor places it directly (no walk-in).
  mood(id: string, m: Mood): void               // face morphs + idle variant
  emote(id: string, e: Emote): void             // one-shot overlay, then resume the task (seated: upper body only)
  hold(id: string, prop: string | null): void   // prop id from props.glb in the right hand ('phone', 'mug', ...)
  // props
  setGear(items: GearItem[]): void        // the player's gear (section 7, "Baked gear"); [] = only the desk default
  setBoxes(units: number): void           // inventory boxes filling a_boxes_* regions (log scale, pop in/out)
  // projection for DOM overlays (menus, labels, bubbles), in canvas CSS pixels; null if not visible/not loaded
  screenRect(key: string): ScreenRect | null     // interactive key or 'actor:<id>'
  screenPoint(actorId: string, where?: 'head' | 'feet' | 'above'): ScreenPoint | null
  onFrame(cb: () => void): () => void     // called after each render; returns the unsubscribe function
  resize(): void                          // also automatic via ResizeObserver on the canvas
  dispose(): void                         // frees GL resources, listeners, loops; restores the canvas style
  // QA / debug only (not for game logic)
  stats(): { calls, triangles, geometries, textures, programs, room, roomMeshes, actors,
             props: { gear, gearIds, boxes, capacity }, speed, hour, yaw, zoom, cut, character }
  debugActors(): { id, task, step, anim, posture, hidden, x, z, y, yaw }[]
  debugAnchors(): { name, x, y, z, yaw }[]
  readonly internals: { renderer, scene, camera, rig, room }
}
export interface GearItem { id: string; anchor?: string }   // 'ring-light' or 'ring_light'; anchor optional ('a_' ok)
export interface Look {
  skin: string; hair: string; hairStyle: HairStyle; top: string; topStyle?: TopStyle
  bottom: string; shoes: string; acc?: Accessory[]; accColor?: string; height?: number /* 0.9..1.1 */; build?: number /* 0.85..1.2 */
}
export type TopStyle = 'tee'|'hoodie'|'polo'|'blazer'|'sweater'|'uniform'
export type HairStyle = 'short'|'messy'|'long'|'bun'|'braids'|'afro'|'buzz'|'curly'|'ponytail'|'bob'|'bald'
export type Accessory = 'glasses'|'cap'|'cap_back'|'beanie'|'flatcap'|'hijab'|'headphones'|'visor'|'scarf'|'beard'|'apron'
export type Mood = 'neutral'|'happy'|'tired'|'stressed'
export type Emote = 'cheer'|'wave'|'stressed'|'talk'

  | { kind: 'idle'; at?: string; anim?: AnimName }              // stand at anchor (or where you are)
  | { kind: 'wander' }                                            // stroll between a_idle_* with idle variants
  | { kind: 'sit'; at: string; anim?: 'sit_idle'|'sit_type'|'sit_think'|'eat_sit' }
  | { kind: 'lie'; at: string }                                   // sleep on a_bed_lie
```

Anchor names in tasks may be given with or without the `a_` prefix; anchors, keys and ids are the ones of section 5.

Behaviour requirements:
- **Camera**: perspective, FOV 28° (vertical), default from the south-east at 40° elevation (31° when zoomed in),
  framing the whole floor with a small margin at any aspect ratio (fit to the floor's bounding box every frame).
  Drag (mouse/one finger) rotates yaw freely with damping and a little coast; wheel/pinch zooms (clamped 0.32..1.25
  of the fit distance); right-drag/two-finger/shift-drag pans (clamped to the floor, more freedom when zoomed in).
  `rotate`, `zoom`, `resetView` animate. Keyboard handled by the game, not the stage.
- **Orbit (title screens)**: `setCameraMode('orbit')` circles the diorama at 5°/s starting from `a_cam`'s yaw, with
  `a_cam`'s elevation and FOV, and REFITS the distance every frame (`ORBIT` in camera.ts): the diorama spans 80% of
  the canvas width (90% on portrait canvases) unless its height binds first, and stays between NDC y −0.98 and +0.6
  through a vertical lens shift (no camera tilt), so the top ~20% of the canvas (the logo band) is always clear and
  the size stays even all the way round. Measured on title_city: ~66% of the width at 16:9 (the apartment roof and
  the billboard reach into the upper third, the band above them is sky), ~50% at 21:9 (height binds), 90% on a phone
  in portrait with the block a little below the middle. Drag still turns it; pan is off.
- **Studio (room `studio`)**: the camera frames ONE person standing on `a_spawn` (a 2 m tall column plus the
  pedestal's front lip) at 9° elevation, FOV 26°, 9% margin, at any aspect (tall portrait canvases fill the width).
  Drag, `rotate` and `resetView` turn the WORLD (pedestal + person) like a turntable while the camera and the lights
  stay put, so the face stays lit; zoom (0.5..1.15) moves toward the face; pan is off. No extra API: the Look editor
  calls `setRoom('studio')`, `setActor('preview', { look })`, `task('preview', { kind: 'idle', at: 'spawn' })`, then
  `setActor` again on every edit (only a changed look is rebuilt).
- **Wall cutaway**: each frame, a wall whose outward normal points toward the camera (dot > 0.2, hysteresis 0.1)
  animates down to a 0.3 m stub (scale on Y around the floor) and hides its parented decor; others animate back up.
  Interactive groups and people never hide. `outside` sectors ({sector}) on the camera's side (dot > 0.3) sink 45 m
  and hide, so tier5's city never stands in front of the room.
- **Picking**: raycast on pointer move (throttled) against interactive groups, actors and the floor. Hover = soft emissive
  glow on the whole group (restored on leave) + `onHover`. A click that was not a drag (< 6 px movement) = `onPick`.
- **Lighting**: hemisphere + one shadow-casting directional "sun" + the `l_*` point lights (on at night, off by day,
  capped at 4 active point lights for performance). `setTimeOfDay` blends 4 keys (dawn 6h, day 12h, dusk 18h, night 22h).
  Neutral tone mapping, sRGB output, soft shadows, a faint room environment map. Background = transparent (the game
  paints the backdrop).
- **Actors**: `SkeletonUtils.clone` of `character.glb`; the look's parts are baked per actor into ONE skinned mesh with
  vertex colours (one draw call per person); AnimationMixer with 0.25 s cross-fades; walking follows the A* path with
  smoothing at 1.35 m/s (x speed), turning smoothly; sit/lie tasks snap the last metre with a short blend so the pose
  lands on the anchor. Anchors are reserved: when several actors target the same anchor, the others queue near it,
  each on its own spot (queuers never overlap), and take the anchor when it frees.
- **Crowd: people never walk through each other** (`src/three/crowd.ts`, pure and unit tested, used by actors.ts):
  - a new walk plans around people standing still (a copy of the walk grid with each still person blocked, radius
    0.37 m); if that finds no path, the plain grid is used;
  - while walking (standing people and walkers are neighbours; seated, lying and hidden people are not): someone
    standing in the corridor ahead is passed with a side-step (away from their side; dead ahead = to the right) at
    reduced speed, and if they stay in the way for 0.35 s the walk is replanned around them (3 times per walk at
    most); someone walking the same way ahead is followed (easing to a stop 0.45 m behind, no overtaking); two walkers
    meeting head-on or crossing: the one with the larger id waits, the other side-steps and goes first; overlapping
    people are pushed apart. Side-steps only move onto free floor;
  - polite doorway: a walker whose remaining path enters the zone around `a_door_exit` / `a_exit_door` (0.95 m) holds
    (idle anim) while anyone else is in that zone; walkers already inside the zone never wait;
  - nobody waits forever: after 3.2 s held, a walker passes through for 1.6 s (Sims-style), then avoids again.
  Seat/bed reservations, the final glide onto an anchor and `leave`/`hidden` are unchanged.
- **Performance**: ≤ 250 draw calls per room, `renderer.info` exposed as `stage.stats()` for QA. Render loop stops when
  `setActive(false)` or the document is hidden. Everything disposes cleanly (no leaks on room swaps: check
  `renderer.info.memory` before/after 10 swaps in QA).
- **Robustness**: a failed GLB load or lost GL context calls `onError` once; the game keeps its 2D scene as fallback.
  `webglAvailable()` is false in tests / Node; `src/three` must not touch `window`/`document` at import time.
- QA hook (dev only, set by the game): `window.__stage = stage`. Lab: `npx vite`, then `/src/three/lab/index.html`
  (query params listed in lab.ts); screenshots: `node scripts/snap3d.mjs "room=studio&actors=1&looks=p05&tasks=idle:spawn"`.

`src/three/react.ts` exports `useStage(canvasRef, opts: Omit<StageOptions, 'canvas'> & { enabled?: boolean })` →
`Stage | null` (creates on mount, disposes on unmount, survives React StrictMode double-mount; `enabled: false` keeps
it unmounted; callbacks always read the latest props).

**Baked gear (one rule for both games).** Some rooms show gear as furniture (tier2's ring light, tier3's camera on a
tripod and two softboxes, the monitors on the tier2..tier5 main desks) and Dropship also passes the player's owned
gear to `setGear`, while Hustle never calls it. The rule (`planGear` in `src/three/math.ts`, unit tested):
1. The room tags every piece that stands for a gear item: extras `{gear:"<props id>"}` on its group (comma list
   allowed). As built: tier2 `ring_light` + main desk `workstation`; tier3 `mirrorless_camera`, `softbox_kit` (both
   softboxes) + main desk `workstation`; tier4 and tier5 main desk `workstation`. `F.ring_light`, `F.camera_tripod`,
   `F.softbox` and `F.workstation(monitors>0, gear_anchor=...)` tag themselves.
2. `setGear` skips any id the room tags (ids normalised: `ring-light` = `ring_light`; duplicates count once). A
   skipped item does not use up an `a_gear_floor_*` anchor. The baked piece always stays visible (Hustle and a
   player who does not own it see it too: it is the room's furniture).
3. Desk items go on `a_gear_desk`, floor items (`ring_light`, `softbox_kit`, `mirrorless_camera`) on
   `a_gear_floor_1`, `_2` in order (more floor items than anchors: the extra is not shown); an explicit `anchor` wins.
4. A bare main desk (tier0, tier1: no monitors, no laptop) carries `a_gear_desk` extras `{default:"laptop_old",
   center:<m>}`. Whenever no computer (`laptop_old`, `laptop_pro`, `workstation`) ends up on `a_gear_desk`, the runtime
   shows the default there, so a desk is never bare: Hustle always gets the laptop, Dropship gets the player's own
   computer instead as soon as it owns one. On a desk with `center`, the computer sits in the middle of the desk
   (a prop wider than the desk, the workstation on tier1, is scaled down to fit) and small gear (phones, mic) sits in
   the gear zone beside it; on a desk that already shows monitors the computer stays in the 0.45 m gear zone and small
   gear sits in front of it.
`stage.stats().props.gearIds` lists what is placed (`laptop_old@gear_desk`, ...).

## 11. As-built notes (from the asset builders)

- **Seat height**: "pelvis 0.46 m" is the underside of the buttocks resting on a 0.46 m seat; the `hips` bone sits at 0.555 m.
  In `sleep` the back surface lies on the root plane.
- **Hand sockets**: with the forearm forward and thumb up, a socket has the character's axes (+Z up along the thumb, −Y
  forward along the fingers). Phones are modelled upright with the screen facing +Y, so they face the head in `phone`/`film`.
- **Face morphs**: only `sleep` and `idle_tired` animate a morph (`sleepy`). A glTF morph track overwrites every morph weight,
  so the runtime sets mood morphs after `mixer.update` and handles blinking itself.
- **`carry`** is upper-body only (layer it over `walk`). Clips only contain channels that change.
- Eyebrows add a second `m_hair` slot on `body`; glasses frames use `m_eye`; `m_acc2` (default #f3f2ef) is the shirt under
  blazer/sweater, the name tag and scarf stripes. Headphones rest around the neck (portrait p02).
- `looks.ts` owns hat/hair substitutions (under cap/beanie/flatcap: messy→short, afro→curly, bun→ponytail; under a visor:
  afro→curly; hijab hides all hair) and `lookColors()` (lip colour derived from skin).
- `height`/`build` are applied by the runtime via bone scale; the mesh has no variants.
- **Lib export**: each furniture group is merged into one child mesh `<group>_mesh` (fewer draw calls). Rooms cost ~23 bytes
  per triangle, so aim for ≤ 80k triangles to stay under 2 MB. `kitchen_run(wall=...)` parents upper cabinets to that wall so
  they hide with it. `workstation(gear_anchor=...)` leaves the desk's left 0.45 m free for Dropship gear props.
- **Walk check**: `*_lie` anchors use a 1.6 m approach radius (king beds). Wall meshes get the same 0.15 m padding.
- Palette addition: `kraft` #c9a36b (shipping boxes). Room root extra addition: `wallT` (wall thickness).

### Runtime as built (deviations from the sketch above, all reflected in section 6)

- **`placeholderActors`** (StageOptions, dev/lab only): when character.glb is missing the lab shows capsule people
  instead of calling `onError`. Games leave it off.
- **People are baked**: each actor's visible parts (body + hair + top add-on + accessories of its look) are merged into
  ONE skinned mesh with the look's colours in vertex colours (one draw call + one shadow draw per person; hair and
  accessory nodes are not toggled at draw time). `setActor` with a new look re-bakes; `height`/`build` scale the
  actor's model (the character's proportions, not per-bone).
- **Room furniture merged by colour**: plain palette materials move into vertex colours and merge per surface class
  (roughness/metalness), per interactive group, per staff desk, and for all static furniture; the special materials
  (`m_screen`, `m_window_*`, `m_lampshade`, `m_neon_*`) keep their own meshes. Furniture shadows draw as one
  position-only caster.
- **Faces**: the runtime drives the face morphs itself (mood targets, blinking, `sleepy` while lying); morph tracks in
  the clips are dropped.
- **`zoom(delta)`**: positive = zoom in (one unit = one 0.8× step of the camera distance); negative = out.
- **Gear**: the baked-gear rule and the desk default (section 7). **Studio** room and framing (sections 5a, 6).
  **Orbit** refits per yaw with a lens shift (section 6). **Crowd** avoidance, planning around still people, polite
  doorway waits and spread-out seat queues (section 6). **Outside sectors** sink on the camera's side (section 5).
- **Camera far plane** reaches 400 m past the fit distance (tier5's city floor lies 34 m below and ~250 m around).
